# 니케(NIKKE) PC 런처 악성코드: 감염 확인과 대응 (한국어 안내)

> 2026년 11월 5일 17시(한국시간) 기준으로 공개된 정보를 개인이 정리한 **비공식 안내**입니다.
> 기본 확인 방법은 직접 열어 보거나 내용이 보이는 명령을 붙여넣는 방식입니다. 보조용 자동 검사 파일(`NIKKE_check.bat`)도 있는데, 메모장으로 열면 내용이 다 보이는 텍스트 파일입니다.

**공식 공지 (11월 5일):** 레벨 인피니트는 11월 5일 네이버 게임 라운지와 공식 카페에 사과문을 내고 경위, 점검 방법, 피해 접수를 안내했습니다.

- **경위:** 일부 게임 서비스에 쓰이던 도메인(insightjs.com)이 9월 27일 10시 59분 제3자에게 넘어갔습니다. 같은 날 15시 41~42분에는 런처가 내려받는 공식 CDN 스크립트 4개가 변조됐습니다. 변조 경로는 아직 조사 중입니다.
- **조치:** 11월 4일 새벽 2시대에 파일 3개를 교체했고, 같은 날 12시 9분 나머지 1개의 CDN 캐시 갱신을 마쳤습니다. 지금 배포 중인 런처는 정상 이용할 수 있다고 밝혔습니다.
- **자동 검사:** 11월 5일 오전 8시부터 PC 런처를 실행하면 악성 프로그램을 검사합니다. 발견되면 동의를 받아 관련 파일과 기록을 지웁니다. 실행 전 웹 브라우저를 모두 닫으라고 안내합니다.
- **점검 대상:** 9월 27일 15시 41분 이후 PC 런처를 한 번이라도 실행한 사람입니다. 모바일만 이용했다면 점검할 필요가 없습니다.
- **피해 접수:** 게임 피해, 외부 서비스 계정 이상, 금전 피해를 공식 고객센터에서 받습니다. 게임 내 보상은 따로 준비 중입니다.

11월 4일 첫 공지는 [PC 런처 이상 상황 안내](https://x.com/NIKKE_kr/status/2117817404399210900)입니다.

## 1. 감염 확인 (30초)

### 윈도우

1. 바탕화면의 니케 아이콘을 우클릭 → **파일 위치 열기**
   (아이콘이 없으면 니케 설치 폴더 안의 `Launcher` 폴더로 갑니다. 예: `C:\NIKKE\Launcher`, 구글 플레이 게임즈판은 `C:\NIKKE_GOOGLE\Launcher`)
2. `intl_service` 폴더 → `debug.log`를 **메모장**으로 엽니다.
3. **Ctrl+F**로 `k2f_chan`을 검색합니다.

| 결과 | 뜻 | 할 일 |
| --- | --- | --- |
| `k2f_chan`이 나옴 | **감염.** 악성코드가 실행됐습니다. 줄 맨 앞 `[1102/201509...]` 같은 숫자가 실행 시각(이 예시는 11월 2일 20:15:09)입니다. | [2. 감염일 때](#2-감염일-때-순서대로) |
| `k2f_chan registered` 바로 다음 줄이 `startup failed: EIO: invalid UTF-8 in string` | 윈도우 사용자 이름이 한글 등일 때 나오는 줄입니다. 악성코드가 공격자 서버에 등록되기 전에 멈췄을 가능성이 높지만, 확실하지 않습니다. | 감염과 똑같이 대응 → [2. 감염일 때](#2-감염일-때-순서대로) |
| 11월 5일 이후 런처 자동 검사에서 악성 프로그램 발견 창을 봤음 | **감염.** 정리에 동의했다면 흔적이 지워져 아래 확인으로는 안 나올 수 있습니다. | [2. 감염일 때](#2-감염일-때-순서대로) |
| 안 나옴 | 감염 흔적 없음 (100% 보장은 아님) | [3. 감염 흔적이 없을 때](#3-감염-흔적이-없을-때) |
| 니케 폴더를 이미 지웠음 | 아래 "폴더를 지웠다면"으로 확인 | |

**니케 폴더를 이미 지웠다면:** 니케 폴더를 지워도 남는 기록이 있습니다. 시작 버튼 우클릭 → **터미널**(또는 Windows PowerShell)을 열고 아래 한 줄을 붙여넣습니다. 파일을 읽기만 합니다.

```powershell
Select-String -Path "$env:APPDATA\nikke_launcher*\tbs_cache\Local Storage\leveldb\*" -Pattern "k2f.agent" -SimpleMatch -List
```

무언가 출력되면 감염, 아무것도 안 나오면 흔적 없음입니다. 구글 플레이 게임즈판(`nikke_launcher_google`) 기록도 함께 찾습니다.

다만 기록이 압축된 파일 안에 들어가 있으면 이 명령으로는 못 찾을 수 있습니다. 확실히 하려면 원 분석자의 검사 도구 [NIKKE-Launcher-Check](https://github.com/MotherSphere/NIKKE-Launcher-Check)(0.4.1 이상, 압축 파일까지 읽음)를 씁니다. Malwarebytes 검사에서 `Trojan.Trace.K2F`나 `Trojan.Loader.K2F`가 나오면 이 악성코드의 흔적이라는 보고도 있습니다.

**감염이라면 크롬 상주 여부도 확인:** 같은 창에 아래를 붙여넣습니다.

```powershell
reg query "HKCU\Software\Classes\CLSID\{E77CC89B-7401-4C04-8CED-149DB35ADD04}"
```

키 내용이 출력되면 런처를 꺼도 크롬 안에서 계속 정보를 훔치는 장치가 깔린 상태입니다. `오류: 시스템이 지정된 레지스트리 키 또는 값을 찾을 수 없습니다.`가 나오면 **정상**, 즉 없는 것입니다. "오류"라는 말에 놀라지 않아도 됩니다.

### 윈도우: 자동 검사 파일 (보조)

위 확인을 한 번에 해 주는 파일입니다. 니케 설치 위치를 알아서 찾고, 결과를 **감염 / 노출 / 흔적 없음 / 니케 없음** 중 하나로 보여 줍니다. 파일과 레지스트리를 읽기만 하고, 아무것도 지우거나 바꾸지 않으며, 인터넷에 접속하지 않습니다.

1. 이 저장소에서 [`NIKKE_check.bat`](NIKKE_check.bat)를 내려받습니다.
2. (권장) 메모장으로 열어 내용을 확인합니다.
3. 더블클릭합니다. "Windows의 PC 보호" 창이 뜨면 **추가 정보 → 실행**을 누릅니다.
4. 10초~1분 뒤 맨 아래에 나오는 결과를 확인합니다.

악성코드 본체를 요청한 기록만 있고 `k2f_chan`이 없으면 **노출**로 나옵니다. 요청이 실패했을 수도 있기 때문입니다.

**원본인지 확인하기 (해시):** 카톡이나 커뮤니티 등 이 저장소가 아닌 곳에서 받았다면, 파일이 있는 폴더에서 터미널을 열고 아래를 붙여넣습니다.

```powershell
Get-FileHash .\NIKKE_check.bat
```

`Hash` 값이 아래 둘 중 하나와 **한 글자도 빠짐없이** 같아야 합니다. 다르면 누군가 고친 파일이니 실행하지 마세요.

| 판 | SHA-256 |
| --- | --- |
| 11월 5일판 (현재) | `B4E32C63E2D46C2B2F0D72239F9F45F3CC08FB9E7063865F5145CA0273242E97` |
| 11월 4일판 (이전) | `E11126DCC7AB28640FE44A69CC8A61E2E35551C091A895ABC6624FB1B54C4760` |

해시는 "이 저장소의 원본과 같은 파일"이라는 것만 보여 줍니다. 안전하다는 근거는 해시가 아니라, 내용을 직접 열어 볼 수 있다는 점입니다. 이전 판도 원본이지만, 공식 후속 공지 전의 안내 문구가 들어 있으니 현재 판을 받으세요.

**테스트 범위:** 11월 4일판으로 감염된 PC 1대(감염으로 판정)와 니케가 없는 PC 1대(니케 없음으로 판정)에서 확인했습니다. 니케가 깔려 있지만 감염되지 않은 PC에서는 아직 확인하지 못했습니다. 11월 5일판은 판정 1곳(본체 요청 기록만 있으면 감염이 아니라 노출)과 안내 문구만 바꿨습니다.

### 스팀덱·리눅스

터미널(Konsole)에 붙여넣습니다. 줄 끝 숫자가 `0`이면 흔적 없음, `1` 이상이면 감염입니다.

```bash
find ~ /run/media -path '*Launcher/intl_service/debug.log' -exec grep -Hc k2f_chan {} + 2>/dev/null
```

### 잘못 알려진 정보

- ❌ "9월 27일 이후 런처를 켰으면 전부 감염" → 변조 스크립트만 거쳐 가고 본체는 안 받은 경우가 많습니다. `k2f_chan`으로 판별합니다.
- ❌ "로그가 실행할 때마다 덮어써진다" → 로그는 계속 쌓입니다. 니케 폴더를 지우지 않았다면 남아 있습니다.
- ❌ "`startup already in progress` 줄이 있으면 감염" → 감염 여부와 상관없이 나오기도, 안 나오기도 합니다.
- ❌ "백신 검사가 깨끗하면 안전" → 윈도우 디펜더가 악성 파일을 못 잡은 사례가 있습니다.

## 2. 감염일 때 (순서대로)

### ① 그 PC에서

- [ ] 니케 런처를 끄고 다시 켜지 않습니다 (작업 표시줄 오른쪽 트레이 아이콘까지).
- [ ] 가능하면 인터넷을 끊습니다.
- [ ] **그 PC에서는 로그인하거나 새 비밀번호를 입력하지 않습니다.** PC를 정리한 뒤에 합니다.

### ② 휴대폰 등 다른 기기로 계정 지키기

각 계정에서 **비밀번호 변경, 2단계 인증, 모든 기기에서 로그아웃** 세 가지를 다 해야 합니다. 쿠키를 훔치면 비밀번호와 2단계 인증 없이도 로그인이 유지되기 때문입니다.

- [ ] **이메일 (지메일, 네이버 메일 등):** 가장 먼저. 이메일이 뚫리면 다른 계정을 전부 재설정당할 수 있습니다.
- [ ] **구글 계정:** 크롬에 비밀번호를 저장했다면 [passwords.google.com](https://passwords.google.com) 목록이 곧 바꿔야 할 계정 목록입니다. 웨일·엣지에 저장한 비밀번호도 똑같이 바꿉니다.
- [ ] **니케(레벨 인피니트) 계정:** 악성코드에 런처에 저장된 니케 로그인 정보를 풀어내는 기능이 있었습니다.
- [ ] **카카오·네이버:** 카카오톡 PC버전을 썼다면 휴대폰 카카오톡의 기기 연결 관리에서 PC 연결을 해제합니다.
- [ ] **디스코드:** 친구들에게 이상한 링크가 퍼지는 경로라 서둘러야 합니다.
- [ ] **스팀 등 게임 계정, 그 밖에 브라우저에 저장해 둔 모든 사이트**

### ③ 돈과 신원

- [ ] **공동인증서**를 PC에 저장했다면 은행 앱에서 폐기하고 재발급합니다.
- [ ] 브라우저에 **카드번호**를 저장했다면 카드사에 재발급을 요청합니다.
- [ ] **신분증 사진이나 주민번호가 든 파일**이 PC에 있었다면:
  - 금융감독원 [파인](https://fine.fss.or.kr)에서 개인정보 노출 사실을 등록합니다.
  - [엠세이퍼](https://www.msafer.or.kr)에서 내 명의 휴대폰 신규 개통을 막아 둡니다 (무료).
- [ ] **크롬에 암호화폐 지갑**(메타마스크, 팬텀 등)이 있었다면 새 지갑(새 복구 문구)으로 옮깁니다.
- [ ] **개발자라면** GitHub·클라우드·AI 도구 토큰과 SSH 키를 폐기하고 재발급합니다.

### ④ PC 정리: 백업 후 윈도우 초기화

원격조종 중에는 공격자가 아무 명령이나 실행할 수 있었습니다. 흔적 몇 개를 지워서는 깨끗하다고 장담할 수 없습니다.

1. 사진, 문서 같은 개인 파일만 백업합니다. 프로그램(.exe), 스크립트, 압축 파일은 옮기지 않습니다.
2. 증거용으로 `debug.log` 사본과 확인 화면 캡처를 보관합니다.
3. 설정의 복구 메뉴에서 **이 PC 초기화 → 모든 항목 제거**를 고릅니다.
4. 초기화 뒤에 새 비밀번호로 로그인합니다.

**초기화가 어렵다면 (공식 수동 정리 방법 요약):**

1. 인터넷을 끊고, 니케와 런처, 크롬을 모두 끕니다 (트레이 아이콘까지).
2. 증거용 `debug.log` 사본을 먼저 보관합니다.
3. 레지스트리 편집기에서 `HKEY_CURRENT_USER\Software\Classes\CLSID\{E77CC89B-7401-4C04-8CED-149DB35ADD04}`를 지우고 재부팅합니다. `HKEY_LOCAL_MACHINE` 쪽에 있는 같은 이름의 키는 정상이니 지우지 않습니다.
4. `%LOCALAPPDATA%\Google\Chrome\User Data\PlatformExperienceHelper` 안에서, 이름이 64자리 영숫자이고 `platform_experience_helper.dll`이 든 하위 폴더만 지웁니다. 상위 폴더 전체는 지우지 않습니다.
5. 니케 설치 폴더의 `Launcher\log\tinyget` 안에서 크기가 약 205,135바이트인 `tinyget.날짜-시각.log` 파일을 지웁니다.
6. `%APPDATA%\nikke_launcher\tbs_cache` 폴더를 지웁니다. 구글 플레이 게임즈판은 `nikke_launcher_google` 폴더 안에 있습니다.
7. 백신을 최신으로 업데이트해 전체 검사를 하고, Windows 보안의 Microsoft Defender 오프라인 검사도 합니다.

11월 5일 이후 런처를 실행하면 자동 검사가 비슷한 정리를 해 줍니다(웹 브라우저를 모두 닫고 실행). 어느 쪽이든 알려진 흔적만 지웁니다. 원격조종 중 다른 프로그램이 깔렸을 가능성까지 없애려면 초기화가 가장 확실합니다.

### ⑤ 지켜보기와 신고

- 내가 하지 않은 로그인 알림이나 2단계 인증 요청은 **절대 승인하지 않습니다.**
- 은행·카드 내역을 며칠간 매일 확인합니다.
- 피해 상담: **118** (한국인터넷진흥원)
- 금전 피해가 생기면: [경찰청 사이버범죄 신고시스템](https://ecrm.police.go.kr)
- **레벨 인피니트 공식 고객센터**에 접수합니다. 게임 피해, 외부 서비스 계정 이상, 금전 피해를 받는다고 공지했습니다. `debug.log` 사본과 확인 화면 캡처를 함께 준비합니다.

## 3. 감염 흔적이 없을 때

1. (선택) 변조 스크립트가 거쳐 간 흔적(노출)이 있는지 보려면 터미널에 아래를 붙여넣습니다. 무언가 출력되면 "본체는 안 받았지만 변조 스크립트는 거쳐 간" 상태입니다. 불안하면 주요 비밀번호를 바꿔 두세요.

    ```powershell
    Select-String -Path "$env:APPDATA\nikke_launcher*\tbs_cache\Code Cache\js\*" -Pattern "insightjs" -SimpleMatch -List
    ```

2. 런처를 다시 쓰기 전에 `tbs_cache` 폴더를 지웁니다. 변조된 옛 파일이 남아 있을 수 있습니다. 위치는 `%APPDATA%\nikke_launcher\tbs_cache`이고, 구글 플레이 게임즈판은 `nikke_launcher_google`, HMT판은 `nikke_launcher_hmt` 폴더 안에 있습니다. 이 폴더에도 흔적이 남으니 1번 확인을 먼저 합니다.
3. 레벨 인피니트는 11월 5일부터 런처를 정상 이용할 수 있다고 안내합니다. 실행 전에 웹 브라우저를 모두 닫으세요. 실행하면 런처의 자동 검사가 한 번 더 확인합니다.
4. 공식 안내대로 백신을 최신으로 업데이트해 전체 검사도 해 둡니다.

## 참고: 감염 중 공격자가 할 수 있었던 일

런처가 켜져 있는 동안:
- PC에서 아무 명령이나 실행하고, 모든 파일을 열어보고 복사
- 모든 모니터 화면 캡처
- 브라우저(크롬, 엣지, 파이어폭스 등)에 저장된 비밀번호와 쿠키
- 니케 런처에 저장된 로그인 정보
- 크롬의 암호화폐 지갑 확장 28종, SSH 키, 개발·클라우드 도구 인증 파일

실행한 명령은 로그에 남지 않아서, 무엇이 실제로 빠져나갔는지는 알 수 없습니다. 그래서 감염이면 "전부 넘어갔다"고 보고 대응합니다.
